## Context

目前頁面透過 `useProgressStore` 的 mark actions 更新六種進度；`main.ts` 以同步 `$subscribe` 將每次 mutation 寫入 localStorage。首頁今日菜單是靜態文字，題庫按需 fetch，文法已有穩定 ID，但讀解子題只有陣列位置。進度碼為 v4；`isProgressPayload` 的寬鬆形狀檢查允許錯誤欄位被正規化成空進度。

本 change 同時改變作答結果、任務、複習和持久化，必須維持單一狀態擁有者。使用者已選擇全部四項功能及兩個問題；其中 streak 現況符合舊規格，本次明確改變產品語意。

主規格目錄目前為空，舊需求僅存在於未封存的 `migrate-to-vite-vue3`。本次獨立產出新能力，不自行同步或封存其他 change；實作時在 `ARCHITECTURE.md` 記錄本 change 對 v4 後續升級、抽牌及 streak 的新決策，保留 D4 對 v2／v3 不遷移的歷史決定。

## Goals / Non-Goals

**Goals:**

- 今日任務可開始、續做、跨頁統計，重整或切換等級不丟失當日進度。
- 四類練習共用一個學習結果入口；錯題可重做，單字可依到期日複習。
- 有效練習觸發 streak；不把錯誤答案當成「沒有學習」。
- v4 使用者保留六欄位與等級／streak 基線，升級至可匯出、匯入和撤銷的 v5。
- 明確且可驗收的第一批題庫擴充，保留既有題目身分。

**Non-Goals:**

- 後端、帳號、雲端同步、多分頁衝突合併、PWA／離線快取、推播。
- FSRS／SM-2、文法或文章的間隔排程、官方模擬考評分與通過率預測。
- 重寫現有題意、擴充全部 7,970 筆單字、取得付費或受版權保護的試題。
- 自行操作瀏覽器、切換 Pages 設定、發佈、合併或封存舊 change。

## Decisions

### D1：以單一學習結果 action 完成一致的狀態轉移

在零 Vue 的 domain 中定義 `StudyItemRef`、`LearningResult` 與純 reducer；Pinia 保持唯一可寫擁有者。`recordLearning(result)` 驗證並一次產生 next state，更新既有掌握紀錄、活動摘要、錯題、單字排程及 streak；頁面不能先 mark 再另外記錄活動。

`LearningResult` 包含 attemptId、穩定題目參照、練習模式、對錯／自評與提交時的時間。日期由注入 clock 按裝置本機時區產生，不接受頁面任意指定「今天」。每個題目實例只提交一次；重做建立新 attemptId。保留最近 2,000 筆結果並以其中 attemptId 去重；此保證涵蓋保留視窗，不承諾永久事件去重。當日任務另按 item key 去重，所以重做不能灌水。

| 輸入 | 有效學習 | 掌握紀錄 | 錯題／排程 |
| --- | --- | --- | --- |
| 翻卡後選「記住了／還不熟」 | 是 | 維持 vKnown／vLearning 互斥 | 不熟進入待複習；兩種評分更新單字排程 |
| 讀音測驗提交答案 | 是 | 不自動標記 vKnown，保留原本手動掌握語意 | 更新錯題與單字排程 |
| 文法提交答案 | 是 | 答對加入 gDone，答錯移除 | 更新錯題 |
| 讀解子題提交答案 | 是 | 同一文章 attempt 全對才加入 rDone | 子題更新錯題；完成文章另產生可去重的完成紀錄 |
| 聽力提交答案 | 是 | 記錄 lDone 與最新 lCorrect | 更新錯題 |
| 開啟、翻面、播放、切換、匯入／恢復、手動「標為已掌握」 | 否 | 手動掌握仍可改六欄位 | 不增加任務、streak 或排程 |

保留最近 90 個本機日的每日唯一 item 集合、文章完成集合與每日計畫；清除舊事件不清除尚存的錯題、單字排程、六欄位或 streak。摘要是近期事件的持久投影，不從被截斷的事件列表重算。

替代方案：各頁自行累加 counter 容易出現同一次作答更新一半；只保存全部事件再重播則容量無界，且題庫變更會影響重播。

### D2：題目參照必須能跨排序、跨版本解析

item key 是序列化 tuple `[level, kind, id]`，避免單字或 ID 中的分隔符撞名。單字沿用目前以 `w` 去重的身份；文法／聽力使用既有 id。讀解文章保留 id，子題新增穩定且全域唯一的 id，另外保存 parent article id。禁止以子題陣列索引或題幹文字作持久身份。

runtime resolver 由題庫 service 依 level/kind 解析參照。未找到的 ID 保留原始進度但顯示「題目已不可用」，不自動計成完成、不崩潰、不用新題替代同一身份。已存在的題幹／答案／解析仍以 JSON 為權威，錯題不複製全文。新增子題 ID 的工具保留既有值並使用持久 high-water mark，不能每次按排序重編。

替代方案：`articleId + index` 較省修改，但在題庫擴充重排後會把錯題指向另一題，故不採用。

### D3：今日任務是固定計畫，完成量由有效活動推導

以 `[localDate, level]` 保存計畫，使用者點「建立今日任務」才取得目前等級所需題庫；首頁正常啟動維持只讀 counts，不預載五級完整題庫。每組任務獨立 pending／error／ready／empty，失敗不變成零題完成；重試只生成尚未 ready 的組別。pending／error 是可重建的 UI 狀態，不能在重整後永久卡在載入中；只有成功生成的目標與 empty 結果保存。請求開始時捕捉日期及等級，晚回應只能寫入原計畫，不能覆蓋切換後的計畫。

預設單字最多 10 個、文法最多 5 題；深入任務由使用者選 1 篇讀解或最多 3 題聽力，開始後當日不切換該分支。每組以實際可用的唯一 items 為目標上限，不重複補齊；無題顯示「此等級目前無可用題目」，不是 100% 完成。

單字優先到期、無排程但待複習、未學，最後才補未到期已學單字；文法優先待複習錯題、未掌握，再補已掌握。讀解／聽力優先未完成或未答對。平手按 stable key，第一次建立後保存所選 ID；刷新、續做與新題加入都不重抽已 ready 的組別。

單字／文法／聽力任務以今日有效作答／評分的不同目標 item 數計完成，不要求答對；讀解以今天完整答完所選文章全部子題計完成，不要求全對。正確率與錯題另呈現，不能把任務完成冒充掌握。建立計畫前的同日有效活動若命中所選 ID，一樣計入。

跨午夜依提交當下日期歸屬；新的日期產生新計畫，舊題仍可練習但不能替昨天補完成。切換等級保留各自計畫。計畫中的 ID 後續失效時顯示不可用，經使用者點修復後只替換失效項，保留其他 ID 與完成量；無可替代題時縮減目標並說明。

開始／續做導向既有學習路由，以 query 表示 `study=daily`、日期與組別；等級仍只由 store 持有，不加入 URL。頁面從保存計畫解析未做目標，不再隨機抽新題。query、日期或等級變更必須重建該輪；無對應計畫或當日已過期時顯示返回今日任務入口，仍允許自由練習。到期單字入口同樣以明確 mode 接入單字頁；結果是否計入任務只看當日目標命中，不看來源頁面。

替代方案：純 counter 最簡單，但無法續做指定題目；每日重抽會讓完成量與畫面目標不一致。

### D4：錯題用持久摘要，複習沿用原練習契約

每個 item 維護 wrongCount、lastWrongAt、lastResultAt、pending 與 lastWrongMode；答錯／自評不熟增加 wrongCount 並 pending，之後答對／自評記住了解除 pending，但保留摘要。翻卡與讀音測驗同一單字共用 item，複習按最後錯誤模式呈現。

首頁新增「錯題複習」入口及 hash `/review` 次路由，不增加第六個底部主分頁。依目前等級、類型篩選，按 lastWrongAt 新到舊、stable key 排序，一輪建立固定清單；重做成功不會立即抽走正在看的題目。題目呈現共用 ChoiceQuestion／練習 presenter，結果仍進 D1；題庫解析與主頁共享 cache。

讀解錯題必須帶文章上下文，只重做錯誤子題不算整篇全對；只有回到整篇並完成完整 attempt 才能更新 rDone。聽力複習沿用語音能力、逐字稿降級與離開／背景停止播放。

替代方案：另存錯題答案與內容容易和更新的 JSON 不一致；直接重寫四套作答 UI 則會分裂結果規則。

### D5：單字採明確的日期階梯，第一版不引入演算法套件

以 `[level, word]` 保存 stage（0–5）、dueOn、lastScheduledOn、lastResult。成功階梯為 1、3、7、14、30 天：第一次有效成功進 stage 1；到期成功再升一級，stage 5 之後仍以 30 天排程。未來到期的提前成功不延後 dueOn。

失敗總是重設 stage 0、dueOn 今天；同日再答對可解除錯題，不能讓 stage 連跳或把剛失敗的單字延到很久之後。同日第一次排程結果記錄 lastScheduledOn；當日再次成功不升級，失敗仍能重設。日期加法用本機日曆，不把一天當固定 86,400,000 毫秒，以涵蓋夏令時間。

「開始到期複習」只抽 dueOn ≤ 今天的唯一單字；一般翻卡與今日任務可再補新字。無到期項顯示明確空狀態，仍可自由練習。v4 的已掌握／待複習單字不推測過去學習次數，升級時用 stage 0、升級當日到期建立基線；大量既有掌握字可能增加到期量，因此每輪仍限制最多 10 張。

替代方案：SM-2／FSRS 需要更多評分與參數，不是目前兩種評分的必要前提；只有 known flag 則無法安排下次日期。

### D6：採 v5 單一儲存文件，保留 v4 升級路徑

`nihongo_dojo_v5` 保存 `{ version: 5, state, backups }`，state 包含原六欄位、level／streak／lastDate，以及活動、日期摘要／計畫、錯題與單字排程。backups 最多 10 份，內容是完整 state，沒有遞迴包含 backups。匯出碼只包含 `{ version: 5, state }`，使用與目前一致的 Unicode 安全編碼；匯入支援完整 v4 envelope 與 v5。

將快照與目前狀態放同一文件，覆寫只需一次 `setItem`，避免原本「快照成功、主資料失敗」的部分成功。移除 `main.ts` 對中間 mutation 的同步寫入，改由 store 的顯式 commit 在完整 reducer 結果生成後寫入一次。一般練習寫入失敗仍可套用記憶體 next state，標示未保存並允許匯出；匯入／恢復寫入失敗則不得套用 next state、修改 backups 或顯示成功。

首次啟動若 v5 不存在，嚴格驗證 v4 的完整六欄位、level／streak／lastDate，轉成 v5；有效 v4 快照同步轉換，最多保留最近 10 份。升級只有成功寫入整份 v5 文件才算完成；不刪除或改寫兩個 v4 keys。寫入失敗仍載入轉換後狀態供當次使用與匯出，顯示尚未持久化，下次啟動可重試。v5 已存在時不可再以 v4 覆蓋它；損毀資料顯示可恢復錯誤並保留原字串，不靜默重置寫回。

嚴格匯入與可信內部正規化分離：要求完整五級容器、正確 value 型別、有限非負整數、合法曆日、陣列 ID 不重複、known／learning 不重疊、lCorrect ⊆ lDone，並檢查新活動／任務／排程欄位和容量限制。未知額外欄位與未知版本拒絕，未知題目 ID 則可保留供 resolver 標為不可用；合法空白進度仍可匯入。無效輸入不可透過 normalize 變成有效空進度，也不可先寫快照。

v4 匯入的任務、錯題、活動預設空白，排程由六欄位建立基線；不從「完成過」推測當天活動。保留 v4 streak／lastDate 作歷史基線，UI 說明升級前為開啟紀錄、升級後才依有效練習。匯入／恢復採完整覆寫不合併；快照一起還原所有新狀態，恢復本身仍產生可撤銷快照。

替代方案：在 v4 格式塞 optional 欄位會讓舊應用匯出時靜默丟棄新紀錄；多個 localStorage keys 分開保存新功能則缺少一致的匯入／恢復邊界。

### D7：連續天數在提交時更新，日期可注入測試

只由 D1 的有效結果更新 streak。首次有效練習為 1；與 lastDate 同日不變、次日加一、間隔更久重設為 1。答錯也算學習；被去重的提交、手動標掌握、匯入與恢復不算。每次提交讀取 clock，跨午夜不需重整；若時鐘倒退，不回退 lastDate 或加算，等日期追上後再依同日／隔日規則處理。

替代方案：在 mount 或 visibilitychange 更新仍把查看畫面當作學習，且無法表達真實有效行為。

### D8：題庫擴充採小批次，結構與內容分別驗收

| 等級 | 文法現有 → 目標 | 讀解現有 → 目標 | 聽力現有 → 目標 |
| --- | --- | --- | --- |
| N3 | 20 → 30 | 1 → 3 | 4 → 7 |
| N2 | 30 → 40 | 2 → 4 | 4 → 7 |
| N1 | 15 → 25 | 1 → 3 | 3 → 6 |

每篇新增文章至少 2 題；所有新增選擇題有 1 個唯一正解、3 個不同誘答及繁體中文解析，聽力有完整日文逐字稿。題材涵蓋日常、工作與公共資訊，難度依等級安排；提供本專案原創的來源註記，不稱為官方題庫。既有 N5／N4 只補讀解子題 ID，不改內容或題數。

擴充 `check:data` 檢查所有 identity、level、必要非空欄位、四選一、文章至少一題與 counts；增加既有資產保護的比較驗證及內容審閱清單。文法沿用 sequence 檔，新增 reading-question sequence 只增不減；增題後更新 counts，首頁分母與進階門檻的文法總數自然增加，需說明新增題會使百分比下降但不刪舊進度。

替代方案：大量一次生成難以審閱；只增加題數而沒有身份與內容檢查會把排程、錯題與進度綁到不穩定資產。

## Risks / Trade-offs

- [新增儲存文件與完整快照可能碰到 quota] → 保留 2,000 結果／90 天摘要／10 快照，錯題與排程不因事件截斷被刪；測試容量失敗並提供完整匯出，不能宣稱永久儲存。
- [v5 匯出不能由舊應用讀取] → 保留原 v4 keys，文件明示前向相容而非雙向同步；回退程式只能看到升級前 v4 狀態，新資料另以 v5 碼備份。
- [任務完成不等於掌握] → 畫面分開顯示完成量、答對數與待複習，讀解任務答完與 rDone 全對是不同契約。
- [裝置日期／時區改變影響每日分組] → 使用提交當下本機曆日，注入 clock 測試午夜／時鐘倒退，不保證跨時區連續天數完全等同原時區。
- [題庫增補的語言品質不能由結構檢查證明] → 每批審閱答案唯一性、自然度與解析，列出尚未完成的人工品質檢查，不標榜官方驗證。
- [舊 change 尚未同步至 main specs] → 不自行封存；實作及後續同步時須保持本次 streak／抽牌／v5 規則優先，避免之後舊 spec 覆蓋新契約。
- [無瀏覽器證據] → 型別、Vitest happy-dom 與資料檢查可驗證邏輯；真實語音、手機版面、鍵盤焦點與線上載入須另獲授權後驗證，不能用 mock 結果代稱已通過。

## Migration Plan

1. 先建立 malformed v4、v4 → v5、v5 往返／快照、重複事件與午夜的回歸案例，再接持久化和 reducer。
2. 補穩定讀解子題 ID 及驗證；接入四種練習，在不改掌握規則下改由統一 action 提交。
3. 依序接排程、錯題、今日任務與首頁入口；每階段保持 v4 升級和 v5 匯出可用。
4. 追加 D8 內容，同步 counts、README 與 ARCHITECTURE；執行 `npm run check`、`npm run build` 及 OpenSpec 驗證。瀏覽器驗證列為未授權的獨立檢查，不執行。
5. 發佈與 Pages 外部設定不在本次授權內。回退應用時保留 v5 key 與匯出碼，不刪除資料；舊應用僅會讀原有 v4，不能聲稱可繼續最新進度。重新升級時以既有 v5 為權威。

## Open Questions

無阻擋實作的待決產品問題。本提案採用 D3 的預設任務量、D5 的單字日期階梯及 D8 的第一批題數；後續調整這些數值須同步對應規格和測試。真實瀏覽器／部署檢查，以及新增內容的最終人工語言審閱，仍須在完成報告中明確標示實際證據。
